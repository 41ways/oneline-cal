## 이 게임의 두 문장

**한 번 놓은 카드는 뺄 수 없다. 같은 카드도 어느 칸에 있느냐로 값이 백 배 갈린다.**

**같은 카드는 줄에서 가장 앞선 한 칸만 발동한다.** 뒤의 것은 그 판 내내 빈 칸과 같다.

```
 [시작]→ +7 → ×2 → 짝×3 → +12 → ^2 → [점수]
   1      8     16     48     60   3600
```

`×2`를 2번 칸에 박으면 8이 되고, 5번 칸에 박으면 1800이 된다.
발라트로가 "손패에서 **무엇을** 낼까"를 묻는다면 이 게임은 "이 카드를 **어디에** 박을까"를 묻는다.
그리고 그 결정은 런이 끝날 때까지 따라온다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `index.html` | 화면, 연출, 진행. 규칙은 안 들고 있음 |
| `engine.js` | 카드 테이블 + 파이프라인 실행기 + 층 곡선. DOM 안 씀 |
| `sim/balance.js` | engine.js를 그대로 불러다 수천 판 돌리는 밸런스 시뮬레이터 |
| `sim/fit-targets.js` | 목표 곡선·무한모드 증가율·되감기 예산 조합을 훑어 제일 맞는 걸 찾음 |
| `sim/early.js` | 앞 세 층이 "완벽하게 둬도 못 넘는 날"인 비율 |
| `sim/fit-curve.js` | 도달 가능한 점수 분포에서 목표 곡선을 분위수로 뽑아냄 |
| `rank/` | 데일리 순위 서버 (Cloudflare Worker + D1). 게임과 **같은 engine.js** 를 번들해 제출된 판을 다시 돌린다 |

게임과 시뮬레이터가 **같은 engine.js**를 쓴다. "돌려본 수치"와 "실제로 도는 게임"이
어긋날 수 없게 하려고 이렇게 나눴다.

```bash
node sim/balance.js 400
node sim/fit-targets.js 120
node sim/early.js
```

## 규칙

- 시작 칸 5개, 최대 10개. 2·4·6·8·10층을 넘으면 칸이 하나 늘어난다
- 시작 손패 `+3` `+7` `×2` 세 장을 배치하고 1층부터 시작
- 층을 넘으면 카드 **4장 중 하나**를 골라 **어느 칸에든** 놓는다.
  이미 찬 칸에 놓으면 덮어쓴다 — 이게 카드를 지우는 유일한 방법
- **같은 카드는 가장 앞선 한 칸만 발동한다.** 뒤의 것은 「무효」가 찍히고 아무 일도 안 한다.
  유일한 예외가 **「복제」** — 이것만 여러 장을 이어 깔 수 있다
- 3·6·9·12층에는 **정비** — 두 칸을 맞바꿀 수 있다. 한 번뿐
- 되감기는 본편(1~8층)에서 **한 판에 딱 한 번**
- 8층까지가 본편, 그 뒤는 무한 모드. 목표 자릿수가 층마다 22%씩 늘고,
  **9층에 되감기 +1(덤), 그 뒤 3층마다 +1** — 그때마다 목표 자릿수도 ×3.3 으로 뛴다
- **총점 = 넘긴 층 점수 + 멈춘 층에서 낸 점수.** 같은 층에서 멈춘 사람끼리도 순위가 갈린다
- 점수에 천장이 없다. 1e15 밑은 정확한 정수, 그 위는 **자릿수(log₁₀)로** 들고 다녀서
  표현 한계가 10^(1.8×10³⁰⁸) 이다. 잘 두는 판은 40층대까지 가고 총점이 10^(10⁹~10¹⁰) 까지 나온다
- 데일리는 그날 **첫 판**만 기록되고, 원하면 이름을 붙여 순위에 올린다

## 튜토리얼

시작 화면 → **튜토리얼**. 여섯 단계, 전부 직접 놓아보는 방식이다.

| 단계 | 가르치는 것 | 장치 |
|---|---|---|
| 1 | 값은 1에서 시작해 왼쪽에서 오른쪽으로 흐른다 | `+7` 한 장만 놓고 실행만 |
| 2 | **자리가 값을 만든다** | `×2`를 앞에 두면 28, 뒤에 두면 40. 목표는 40 |
| 3 | 조건 카드는 **앞칸이 만든 값**에 반응한다 | `홀+15`는 시작값 1(홀수) 앞에서만 발동 |
| 4 | 줄이 차면 **덮어쓰는 수밖에 없다** | 네 칸이 `+3 +7 +12 +30`. 무엇을 희생할지 고른다 |
| 5 | **같은 카드는 앞의 것만 발동한다** | 통과할 수 없는 단계. 「무효」를 한 번 당해보게 함 |
| 6 | 되감기는 **무엇을 반복할지** 정하는 것 | `↩2`를 반복시킬 구간 뒤에 둬야 함 |
| 7 | 본편 구조 요약 | 층·보상·정비·되돌릴 수 없음 |

설계 원칙 두 가지.

**정답 칸이 반드시 하나뿐이다.** 통과할 수 있는 단계는 모두 네 칸 중 한 곳만 목표를 넘는다.
"대충 놔도 통과"가 한 번이라도 생기면 그 단계는 아무것도 가르치지 못한다.

**틀리면 왜 틀렸는지가 화면에 남는다.** 실행하면 칸마다 그 시점의 값이 찍히고
지워지지 않는다. 2단계에서 `×2`를 앞에 놓으면 `8 → 16 → 28`이 그대로 보여서,
힌트를 읽기 전에 이미 이유를 알게 된다.

운 카드(`50%×6` `25%×20`)는 튜토리얼에 안 나온다. 배우는 중에 운이 끼면
자기가 뭘 잘못했는지 알 수가 없다.

## 순위 서버

`https://oneline-rank.41ways.workers.dev` — Cloudflare Workers 무료 플랜, 저장소는 D1.
허브 채팅(`norara-chat`)과는 아무것도 나누지 않는 별개 Worker 다. D1 을 쓴 건
채팅·게임 서버가 나눠 쓸 Durable Object 무료 시간을 순위표가 갉아먹지 않게 하려고.

**점수를 믿지 않는다.** 브라우저는 "한 판 동안 둔 수"(시작 손패를 놓은 칸, 층마다
정비·고른 카드·놓은 칸)만 보낸다. 서버가 게임과 똑같은 `engine.js` 로 그 수순을
처음부터 다시 돌려 점수를 직접 계산한다. 데일리는 날짜로 시드가 정해지니
어떤 카드가 나왔는지도 서버가 안다 — "안 나온 카드를 놨다", "못 넘은 층을
넘었다"는 제출은 재생 중에 거절된다(422).

| 길 | 하는 일 |
|---|---|
| `GET /api/top?day=<날짜번호>&me=<pid>` | 그날 위 20명 + 내 자리 |
| `GET /api/best?me=<pid>` | 역대 — 모든 날에서 한 사람당 가장 좋은 판 하나씩, 위 20명 + 내 자리 |
| `POST /api/submit` `{ rules, day, pid, name, moves }` | 재생해서 기록. 한 사람(pid)은 하루 한 줄, 첫 판만 |

- 올리기(POST)는 `wrangler.toml` 의 `ALLOW_ORIGINS` 페이지와 localhost 에서만 받는다.
  게임 주소가 바뀌면 거기에 덧붙이면 된다. 보기(GET)는 어디서든
- pid 는 브라우저가 만든 무작위 아이디(localStorage). 이름이 아니다
- 순위는 총점(자릿수) 순, 같으면 먼저 올린 사람이 위
- 날짜가 바뀌어도 기록은 지우지 않는다. 오늘 순위는 그날 판끼리, 역대는 전부에서 뽑는다
- 두 순위 모두 **지금 규칙 번호(`RULES`)의 판끼리만** 센다. 규칙이 다른 판은 점수를 견줄 수 없다
- 역대 순위의 **시드를 누르면 그날 판을 연습**할 수 있다. 같은 시드라 카드도 실행 결과도 그날과 똑같고,
  연습 판은 순위에도 오늘 기록에도 남지 않는다. **오늘 시드는 오늘 첫 판을 끝낸 뒤에만** 연습된다 —
  첫 판 전에 연습으로 카드를 미리 볼 수 있으면 "첫 판만 기록"이 의미가 없어진다

```bash
node rank/test-replay.js          # 봇 360판을 서버 재생과 대조 + 조작 제출 6종 거절 확인
cd rank
npx wrangler dev --port 8811      # 로컬 (게임은 index.html?api=http://localhost:8811)
npx wrangler d1 execute oneline-rank --remote --file=schema.sql   # 처음 한 번
# (2026-09-11 이전에 만든 D1 이라면 migrate-001-rules.sql 도 한 번)
npx wrangler deploy
```

**게임 규칙을 바꾸면 `engine.js` 의 `RULES` 번호를 올리고 순위 서버도 다시 배포한다.**
서버는 배포할 때 번들된 `engine.js` 로 재생하므로 규칙이 다른 화면이 둔 판은 점수가
달라진다. 번호가 다른 제출은 "새로고침해 주세요"(409)로 돌려보낸다.

## 카드 추가하는 법

`engine.js`의 `CARDS`에 항목 하나 붙이면 뽑기 목록·칸 표시·설명에 자동으로 붙는다.

```js
pos: { n:'자리값', g:'자리×6', r:'common', d:'놓인 칸 번호 곱하기 6을 더한다. 뒤에 놓을수록 크다',
       fx:function(S){ ADD(S, (S.i+1) * 6); } },
```

필드

- `n` 이름 / `g` 칸에 찍히는 짧은 글자 / `r` 등급(`common` `uncommon` `rare` `legend`) / `d` 설명

`fx(S)`에서 쓸 수 있는 것

| 이름 | 설명 |
|---|---|
| `S.v` | 지금 흐르는 값 — `{ n, L }` 쌍. 직접 만지지 말고 아래 함수를 거친다 |
| `S.i` | 이 카드가 놓인 칸 번호 (0부터) |
| `S.line` | 줄 전체 |
| `S.mem` | 저장해둔 값 (역시 쌍) |
| `S.loops` | 남은 되감기 |
| `S.skip` | true로 두면 다음 칸을 건너뜀 |
| `S.jump` | 0 이상으로 두면 그 칸으로 점프 |
| `S.last` | 직전에 실행된 칸 번호 |
| `S.rnd()` | 난수 |
| `ADD(S,n)` `MUL(S,n)` | 값 조작. **역전 카드를 타려면 반드시 이 둘을 거쳐야 한다** |
| `vSq` `vDivN` `vSet` `vAddV` | 제곱·나누기·못박기·쌍끼리 더하기 |
| `vEven` `vLtN` `vGeN` | 짝수인가 / k 보다 작은가 / k 이상인가 |
| `S.acted = true` | 이 카드가 뭔가 했다는 표시. 안 켜면 화면에 「그대로」로 찍힌다 (`ADD` `MUL` 은 알아서 켬) |

효과는 왼쪽 칸부터 순서대로 실행된다. 되감기가 걸리면 인덱스가 뒤로 가고,
그 구간이 다시 흐른다.

## 밸런스 — 시뮬레이터가 잡아낸 것들

프로토타입을 만들면서 `sim/`이 세 번 게임을 구해냈다. 남겨둔다.

**1. 제곱을 루프에 넣으면 게임이 5층에서 끝난다**
`^2` 와 `↩2` 가 같은 줄에 있으면 v → v² → v⁴ → v⁸ 이 되어 다섯 층 만에
값 천장(1e15)에 닿았다. 그 뒤로는 무엇을 집든 어디에 두든 결과가 같아진다.
→ 지수는 한 판에 한 번만, 그리고 배수 상한(제곱 1만 배, 세제곱 100만 배).

**2. 배수 상한은 전부 잘못된 답이었다**
`^2`가 되감기·복제와 겹쳐 폭발하는 걸 막으려고 배수 상한(1만 배), 사용 횟수
제한, 자물쇠 표를 차례로 붙였다. 전부 같은 병을 만들었다 —
**"값을 제곱한다"고 적힌 카드가 제곱을 안 한다.** 화면의 숫자와 카드 설명이
어긋나면 그건 플레이어에게 그냥 버그다.
→ 상한을 전부 걷어내고 규칙 하나로 바꿨다. **같은 카드는 앞의 것만 발동.**
제곱은 언제나 진짜 제곱이고, 대신 두 장을 겹쳐 쌓을 수 없다.

**3. 지수가 열리면 목표를 비율로 찍을 수 없다**
상한을 걷고 나니 같은 8층에서도 점수가 하위10% `1e5.8`, 상위10% `1e113.8` —
**108자릿수 차이**가 났다. 어떤 목표선을 그어도 "지수 카드를 뽑았나"만
묻는 게 된다. 「같은 카드는 앞의 것만」 규칙을 넣고서야 폭이 14자릿수로
내려와 선 하나로 자를 만해졌고, 그제야 분위수로 곡선을 딸 수 있었다.

**4. 안 보이는 규칙은 플레이어에게 그냥 버그다**
`^2`를 두 장 깔았는데 두 번째가 ×2로만 먹히는 걸 보고 "계산이 왜 안 되냐"는
질문이 나왔다. 규칙 자체는 맞았지만(빼고 재보니 8층 클리어가 31%→43%,
6층 이후 통과율이 93~100%로 후반이 통째로 공짜가 됐다) 화면에 아무 표시가 없었다.
→ 앞칸에 같은 카드가 있는 칸은 **「무효」 표를 달고 글자를 지운다.** 보상 후보에도
"이미 N번 칸에 있다"는 경고가 붙고, 배치 전 미리보기에도 뜬다.

**5. `저장 → 역전 → 불러오기`도 같은 구멍이었다**
역전 아래에서 `호출`이 곱셈이 되면 `v × mem` 인데 mem이 곧 v라 결국 제곱이다.
→ 호출만 `ADD`를 안 거치고 값을 직접 더한다. 역전도 한 판에 한 번만.

**6. 데일리는 초반 실패율을 그대로 못 쓴다**
원래 곡선은 완벽하게 둬도 2층에서 19%가 죽었다. 싱글 로그라이크면 괜찮은
수치지만, 데일리는 접속한 모두가 같은 시드로 돌기 때문에 그 19%가 그대로
**"오늘은 전원 2층에서 전멸하는 날"** 의 비율이 된다.
목표를 낮춰도 5%가 안 없어졌는데, 원인이 난이도가 아니라 뽑기였다 —
`Σ자릿수` `건너뜀` `기억`처럼 그 자체로는 점수를 못 올리는 카드로만
후보가 채워지는 날이 있었다.
→ 앞 세 층은 후보 한 자리를 반드시 값을 올리는 카드로 채운다. 2.7%로 내려감.

**7. 숫자 천장은 숫자로 못 올린다** — 제보로 잡힌 것
"얻은 숫자랑 표기되는 숫자가 다르다"는 제보가 왔다. 1e300 천장이 복제가 만든
1.3e305 를 1e300 으로 자르고, 뒤에 붙은 층×25(×700)는 분명 일을 했는데 천장에
다시 잘려 「그대로」로 찍혔다. 28층 목표는 수의 한계를 넘어 `∞` 가 됐고
"∞배 모자랍니다"가 떴다. 자바스크립트 수는 1.8e308 에서 끝나 천장을 거기까지
올려도 한 층도 안 늘어난다.
→ 값을 `{ n, L }` 쌍으로 바꿨다. 1e15 밑은 정확한 정수(짝·홀, <100 같은 판정이
여기서만 뜻이 있다), 그 위는 자릿수만. 무작위 줄 6만 개로 예전 엔진과 대조해
1e15 밑은 한 끝도 안 달라진 걸 확인했다. 「그대로」도 "값이 안 변했나"가 아니라
"카드가 실제로 뭔가 했나"로 판정한다 — 1e20 에 +30 처럼 일은 했는데 표기 자릿수에
안 잡히는 경우까지 「그대로」로 찍히면 같은 오해가 다시 생긴다.

**8. 천장을 없앴더니 다들 같은 데서 멈췄다**
숫자 한계를 풀자 이번엔 "개나소나 다 상한에 닿는다"는 말이 나왔다. 재 보니 잘 두는
판의 90%가 23~27층, 총점 10^200~10^375 한 구간에 몰려 있었다. 한 줄 점수의 상한은
"한 판에 제곱이 몇 번 걸리나"가 정하는데(제곱 1장 + 바로 뒤 복제 1장 = 한 바퀴에 2번),
되감기가 1번뿐이라 누구든 같은 벽에 닿았던 것.
→ 무한 모드에서 되감기를 늘린다. 되감기만 늘리면 줄이 목표보다 빨리 커져
판이 안 끝나서(8층마다 +1 로도 다섯에 하나가 150층까지 생존), 늘 때마다 목표
자릿수도 ×3.3 으로 뛰게 했다. 9층의 첫 +1 은 도약 없이 준다 — 거기서부터 뛰게 하니
8층을 넘긴 판의 9층 통과율이 92% → 74% 로 떨어져 본편 끝이 절벽이 됐다.
잘 두는 판 기준 상위 10% 25층 → 43층, 총점 최고 10^365 → 10^(2×10^10).
본편(1~8층)은 한 끝도 안 바뀌었다.

### 지금 수치

`node sim/balance.js 300` 기준. 완벽하게 두는 시뮬레이터(탐욕)가 8층을 40%,
평균 8.8층. 사람이 잡으면 이보다 한참 낮다.

| 원형 | 평균 도달층 | 8층 클리어 |
|---|---|---|
| 탐욕 (섞어서 최선) | 8.8 | 40% |
| 도박 | 5.8 | 25% |
| 곱셈 | 5.0 | 23% |
| 성장 | 5.3 | 20% |
| 루프 | 5.2 | 18% |
| 기억 | 3.5 | 11% |
| 조건 | 3.5 | 7% |
| 무작위 (대조군) | 0.2 | 0% |

무작위가 0.2층이라는 게 이 게임의 존재 이유다 — 카드가 아니라 배치가 점수를 만든다.

한 축만 고집하는 원형이 전부 탐욕보다 못하다. 줄 하나에 시동(덧셈)·증폭(곱셈)·
마무리(조건)가 다 들어가야 해서, 이 게임은 몰빵보다 역할 분배 쪽이 맞다.
`조건`과 `기억`이 한 자릿수로 처지는 건 아직 덜 다듬어진 부분.
